# LinkedIn post

The post goes out under the user's name to colleagues, friends and recruiters. Every claim in it must be true of the site as it is today.

## 1. Gather the facts first

Do not write from memory.

- **Live URL:** it must exist and load. If the site is not public yet, say so and stop at a draft.
- **Repository URL**, if the user wants it in the post.
- **Catalogue numbers:** read them from the live overview page or from the data (record count, countries, latest source check). Use the same numbers the site shows.
- **A timely hook**, if there is one: for example a programme whose deadline is days away. Check the date against the data.
- **What the user wants from readers:** try it, give feedback, share with students, suggest programmes.

Ask the user for anything personal the post needs and you do not know: their degree, university, why they built it. Do not invent a backstory.

## 2. Write it

- First person, as a student who built something useful. Plain and specific. No hype words, no emoji walls.
- The first two lines must work on their own; LinkedIn hides the rest behind "see more".
- Say what it is, who it is for (undergraduates in life sciences looking for research internships in Europe), and what is different: every fact carries its official source and the date it was checked, and unknowns are labelled instead of guessed.
- Say what it is not: not a live feed, not every programme, Europe only for now. Honest limits read as credibility.
- Do not write "verified", "all internships", "always up to date" or "official". Do not name or criticise other sites.
- Mention that it was built with AI assistance only if the user wants that; ask.
- End with one clear request and the link. LinkedIn tends to show posts with a link in the body to fewer people, so offer both versions: link in the post, or link in the first comment.
- Aim for 900–1,300 characters. Three to five relevant hashtags at the end.

Give two variants with different openings, and suggest what to attach: a short screen recording of the overview's 3D radar works better than a static screenshot.

## 3. Approval

Show the drafts in the conversation. Revise until the user approves one **exact** final text. Approval of a draft is not approval to post.

## 4. Posting

Only when the user explicitly says to post that text:

- Preferred: the user pastes it themselves.
- Or, if they ask Claude to post it: use Claude in Chrome, where the user is already signed in. Never type a password or create an account. Paste the approved text unchanged, attach what the user chose, and stop for a final "post it" before pressing Post.
- Afterwards, report the post's URL and confirm the link in it opens the live site.
